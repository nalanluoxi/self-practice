## 二、问题根因回顾

### 2.1 字体缺失

- **根因 1**：`onResponse` 过滤条件只有 `javascript / css / image`，字体的 content-type（`font/woff2`、`application/x-font-ttf` 等）被跳过，字体文件从未被收集
- **根因 2**：Chrome 字体懒加载机制——只有页面上有元素实际使用该字体且元素可见时，才会触发字体文件网络请求，即使修了 onResponse 过滤条件，仍存在字体请求不触发的场景
- **兜底方案**：对已下载的 CSS 内容做后处理，正则提取 `@font-face` 中的 `url()` 引用，主动 HTTP 下载缺失的字体

### 2.2 图片缺失（视口外图片未触发）

- **根因 1（主因）**：懒加载图片只有滚动到视口附近才触发请求。当前 Phase1 navigate 后只等 3 秒且不滚动，`IntersectionObserver` 判断视口外图片"不在视口内"，不发请求，`onResponse` 收不到
- **根因 2**：等待策略为 `DOMCONTENTLOADED`，只代表 HTML 解析完，图片请求尚未发出，等待不足
- **根因 3**：Context 的 viewport 固定（如 1280x800），浏览器懒加载判断范围也基于此 viewport，viewport 以下的图片即使存在也不触发

### 2.3 resources.tsv 只记录成功资源

- **根因**：遍历 `collectedResponses` 时有 `body != null && body.length > 0` 的过滤条件，body 为空（404/403/304 等）的资源不写入 TSV，导致无法观测失败情况

### 2.4 无资源下载统计

- **根因**：目前只有 `phase1` 整体成功/失败的 CAT 打点，没有单条资源粒度的成功/失败统计，无法按类型分析下载成功率

### 2.5 MQ 消息下游扫描目录并发低

- **根因**：`ScreenshotResultMessage.s3DirKey` 只携带目录前缀，下游消费时需调用 S3 `ListObjects` 扫描整个目录才能得知有哪些文件，`ListObjects` 是串行 IO，限制了下游并发

### 2.6 Phase2 无法灰度关闭

- **根因**：截图 + JS 框选交互（Phase2）是固定执行的，没有开关，无法在线上验证关闭该阶段对吞吐量的提升效果

### 3.1 字体文件补充下载

**改动文件：`ScreenshotPlaywrightService.java`**

#### 步骤 1：onResponse 新增 font 类型收集

当前（第 436 行）：
```java
if (contentType.contains("javascript") || contentType.contains("css") || contentType.contains("image")) {
    collectedResponses.add(response);

```

改为（新增 font 判断）：
```java
if (contentType.contains("javascript") || contentType.contains("css")
        || contentType.contains("image") || contentType.contains("font")
        || response.request().resourceType().equals("font")) {
    collectedResponses.add(response);
}
```

同时在 `collectedResponses` 遍历时 type 分类加上 `font`：
```java
if (contentType.contains("javascript")) {
    type = "js";
} else if (contentType.contains("css")) {
    type = "css";
} else if (contentType.contains("font") || response.request().resourceType().equals("font")
        || respUrl.matches(".*\\.(woff2?|ttf|eot|otf)(\\?.*)?$")) {
    type = "font";
} else {
    type = "image";
}
```

`deriveLocalName` 中增加 font 后缀映射，优先保留原始扩展名（woff2/ttf/eot/otf）。

#### 步骤 2：CSS 后处理补充字体（兜底）

在 `collectedResponses` 遍历完成、`resources.tsv` 生成之后，插入 CSS 后处理逻辑：

```
对所有 type=css 的已下载 CSS 文件：
    → 正则提取 @font-face 中的 url() 引用
      正则：url\(['"]?([^'")]+\.(?:woff2?|ttf|eot|otf)[^'")\s]*)['"]?\)
    → 对提取出的每个字体 URL：
        - 相对路径用 CSS 原始 URL 做 resolve（java.net.URL）
        - 过滤已在 collectedResponses 中收集的 URL（去重）
        - HttpClient 直接请求下载（走代理，超时 10s）
        - 写入 assets/ 并追加 resources.tsv
```

字体补充功能直接上线，无需灰度开关。

### 3.2 图片资源完整性提升

**改动文件：`ScreenshotPlaywrightService.java`**

#### 步骤 1：等待策略改为 LOAD

当前（第 448 行）：
```java
.setWaitUntil(WaitUntilState.DOMCONTENTLOADED)
```

改为：
```java
.setWaitUntil(WaitUntilState.LOAD)
```

`LOAD` 事件等待所有资源（含非懒加载图片）加载完成，比 `DOMCONTENTLOADED` 更充分。

#### 步骤 2：Phase1 加分步滚动触发懒加载

> **背景**：当前代码 Phase1 和 Phase2 已合并为同一个 Context + 同一次 navigate（`mergedPage`），无需两次 navigate。Phase1 滚动完成后回到顶部，Phase2 从 `(0,0)` 按 grid 截图，两者完全兼容。
>
> **为何选分步滚动而非一步跳底部**：`IntersectionObserver` 判断图片是否进入视口依赖视口位置连续经过，一步跳到底会跳过中间区域的懒加载图片；分步滚动（每次一个视口高度）可确保每个区域都经过视口，触发更完整。

在 `waitForTimeout(2000)` 之后、`html = mergedPage.content()` 之前插入：

```java
// 分步滚动触发懒加载（受 Lion 开关控制）
if (lazyLoadScrollEnabled) {
    try {
        Object scrollInfo = mergedPage.evaluate(
            "() => ({ pageH: Math.max(document.body.scrollHeight||0, document.documentElement.scrollHeight||0) })");
        int scrollPageH = (scrollInfo instanceof Map && ((Map<?,?>)scrollInfo).get("pageH") instanceof Number)
            ? ((Number)((Map<?,?>)scrollInfo).get("pageH")).intValue() : viewportHeight;
        int scrollStep = viewportHeight;
        for (int y = scrollStep; y < scrollPageH; y += scrollStep) {
            mergedPage.evaluate(String.format("window.scrollTo(0, %d)", y));
            mergedPage.waitForTimeout(300);
        }
        // 滚回顶部，保证 HTML snapshot 和 Phase2 截图起点一致
        mergedPage.evaluate("window.scrollTo(0, 0)");
        mergedPage.waitForTimeout(500);
    } catch (Exception e) {
        log.warn("phase1 lazy load scroll failed, url={}", request.getUrl(), e);
    }
}
```

同步将 `waitForTimeout(3000)` 改为 `waitForTimeout(2000)`：`LOAD` 策略本身比 `DOMCONTENTLOADED` 更充分，不再需要额外等待 3 秒。

**每步等待 300ms 说明**：短于 Phase2 的 500ms（Phase2 需等截图稳定），Phase1 仅需等网络请求触发，300ms 足够 `IntersectionObserver` 回调发出图片请求；如网络较慢可调至 400ms。

Phase1 分步滚动直接上线，无需灰度开关。

### 3.7 HTML 解析补充下载缺失图片（srcset 变体 + 懒加载兜底）

**改动文件：`ScreenshotPlaywrightService.java`**

#### 背景

3.2 方案通过分步滚动 + LOAD 策略，能触发懒加载图片的网络请求，由 `onResponse` 捕获。
但对于 `srcset` 响应式变体，浏览器在任何 viewport 下都只请求**最匹配当前宽度的那一个尺寸**，其余尺寸变体永远不会有网络请求，`onResponse` 无法捕获。

例如：
```html
<img srcset="img-p-500.avif 500w, img-p-800.avif 800w, img-p-1080.avif 1080w, img-p-1600.avif 1600w"
     src="img.avif">
```
viewport=1280px 时只请求 `-p-1080`，其余 3 个变体在爬取阶段永远缺失。
离线渲染时若使用不同 viewport，会选到不同变体，导致缓存命中失败。

#### 解决思路

```
第一步（现有）：onResponse 捕获浏览器实际请求的图片
  → 得到 N 个（受 viewport 和懒加载限制）

第二步（新增）：解析 HTML 文本，收集所有图片 URL
  → 扫描 img[src]、img[srcset]、img[data-src]、img[data-srcset]、picture source[srcset]
  → 得到 HTML 里写的全部图片 URL（包含所有尺寸变体）

第三步（新增）：取差集
  → HTML 里有 但 onResponse 未捕获的 = 缺失 URL

第四步（新增）：对缺失 URL 主动发 HTTP 请求下载
  → 上传 S3，追加进 resources.tsv
```

#### 步骤 1：解析 HTML 收集全部图片 URL

在 `supplementFontsFromCss(...)` 调用之后、`resourcesTsv = tsvBuilder.toString()` 之前，调用新增方法：

```java
supplementImagesFromHtml(html, request.getUrl(), collectedImageUrls, nameCount,
    tsvBuilder, uploadedKeys, s3DirKey, domain, proxy);
```

`supplementImagesFromHtml` 方法实现（与 `supplementFontsFromCss` 结构对称，下载逻辑统一复用 `downloadWithProxy`）：

```java
private void supplementImagesFromHtml(String html, String pageUrl, Set<String> cachedImageUrls,
        Map<String, Integer> nameCount, StringBuilder tsvBuilder,
        List<String> uploadedKeys, String s3DirKey, String domain, Proxy proxy) {
    if (StringUtils.isBlank(html)) return;
    Document doc = Jsoup.parse(html, pageUrl);
    Set<String> allImageUrls = new LinkedHashSet<>();

    // img src + data-src + srcset + data-srcset
    for (Element img : doc.select("img")) {
        String src = img.absUrl("src");
        if (StringUtils.isNotBlank(src)) allImageUrls.add(src);
        String dataSrc = img.absUrl("data-src");
        if (StringUtils.isNotBlank(dataSrc)) allImageUrls.add(dataSrc);
        parseSrcset(img.attr("srcset"), pageUrl, allImageUrls);
        parseSrcset(img.attr("data-srcset"), pageUrl, allImageUrls);
    }
    // picture > source[srcset]
    for (Element source : doc.select("picture source[srcset]")) {
        parseSrcset(source.attr("srcset"), pageUrl, allImageUrls);
    }

    // 取差集：HTML 里有 但 onResponse 未捕获的（含 srcset 所有尺寸变体）
    for (String imgUrl : allImageUrls) {
        if (cachedImageUrls.contains(imgUrl)) continue;
        cachedImageUrls.add(imgUrl);  // 先占位，防重
        try {
            byte[] body = downloadWithProxy(imgUrl, proxy);
            if (body != null && body.length > 0) {
                String localName = deriveLocalName(imgUrl, "image", nameCount);
                String assetKey = s3DirKey + "assets/" + localName;
                s3Service.uploadScreenshotBytes(assetKey, body, "application/octet-stream", domain);
                uploadedKeys.add(assetKey);
                tsvBuilder.append(imgUrl).append("\t").append(localName)
                          .append("\t").append("image").append("\t").append("200").append("\n");
                Cat.logEvent("screenshot.resource.supplement.success", domain + "::image");
            } else {
                tsvBuilder.append(imgUrl).append("\t").append("null")
                          .append("\t").append("image").append("\t").append("0").append("\n");
                Cat.logEvent("screenshot.resource.supplement.fail", domain + "::image");
            }
        } catch (Exception e) {
            log.warn("supplement image download failed, url={}", imgUrl, e);
            Cat.logEvent("screenshot.resource.supplement.fail", domain + "::image");
        }
    }
}
```

#### 步骤 2：srcset 解析工具方法

```java
private void parseSrcset(String srcset, String baseUrl, Set<String> result) {
    if (StringUtils.isBlank(srcset)) return;
    // srcset 格式：url1 500w, url2 800w, url3 2x ...
    for (String part : srcset.split(",")) {
        String url = part.trim().split("\\s+")[0];
        if (StringUtils.isNotBlank(url)) {
            try {
                // 处理相对路径
                String absUrl = new URL(new URL(baseUrl), url).toString();
                result.add(absUrl);
            } catch (Exception ignored) {
                result.add(url);
            }
        }
    }
}
```

#### 插入位置

```
当前流程：
  collectedResponses.clear()
  → supplementFontsFromCss(...)    ← 字体兜底（3.1）
  → resourcesTsv = tsvBuilder.toString()

改为：
  collectedResponses.clear()
  → supplementFontsFromCss(...)    ← 字体兜底（3.1）
  → supplementImagesFromHtml(...)  ← 图片 srcset 兜底（3.7，新增）
  → resourcesTsv = tsvBuilder.toString()
```

#### 效果预期

| 缺失类型 | 数量（此 case） | 3.2 分步滚动效果 | 3.7 HTML 解析效果 |
|---------|--------------|---------------|----------------|
| srcset 尺寸变体 | 20个 | 无帮助 | **全部补充** |
| 懒加载图片（HTML里有 src） | ~10个 | 大部分能触发 | **兜底补全** |
| 首屏外图标 SVG | 6个 | 大部分能触发 | **兜底补全** |

3.2 和 3.7 互补：3.2 通过滚动触发 `onResponse`（性能最优），3.7 通过解析 HTML 兜底补全 `onResponse` 遗漏的（覆盖最全）。

### 3.3 resources.tsv 记录全部资源（含失败）

**改动文件：`ScreenshotPlaywrightService.java`**

当前逻辑（第 478 行）只有 body 非空才写入 TSV：
```java
if (body != null && body.length > 0) {
    // 上传 + 写 TSV
}
```

改为：body 非空时正常上传并记录，body 为空时也写入 TSV，localName 记为 `null`：

```java
byte[] body = resp.body();
if (body != null && body.length > 0) {
    String assetKey = s3DirKey + "assets/" + localName;
    s3Service.uploadScreenshotBytes(assetKey, body, "application/octet-stream", domain);
    tsvBuilder.append(respUrl).append("\t")
            .append(localName).append("\t")
            .append(type).append("\t")
            .append(resp.status()).append("\n");
} else {
    // body 为空（404/403/304 等），记录但不上传，localName 写 null
    tsvBuilder.append(respUrl).append("\t")
            .append("null").append("\t")
            .append(type).append("\t")
            .append(resp.status()).append("\n");
}
```

TSV 格式保持不变：`url\tlocalName\ttype\tstatus`，其中失败行 localName 为字符串 `"null"`。

> **说明**：304 Not Modified 的 body 也为空，按同样逻辑处理（localName=null，status=304）。
> `Cache-Control` 保持现有的 `max-age=0`，已能大幅减少 304 的出现。

### 3.5 MQ 消息 s3DirKey 改为携带所有资源完整路径列表

**背景**：当前 `s3DirKey` 只存储目录前缀（如 `screenshot/20260526/xxx/`），下游需调用 S3 `ListObjects` 扫描目录才能得知有哪些文件，`ListObjects` 是串行 IO，限制了下游并发。

**方案**：复用 `s3DirKey` 字段，**不新增任何字段**。将其值从"目录前缀字符串"改为"所有上传成功文件路径的 JSON 数组字符串"（`List<String>` 序列化）。

**改动文件：`ScreenshotPlaywrightService.java` + `ScreenshotService.java`**

#### 改动点 1：ScreenshotPlaywrightService — 收集所有上传路径

在 `ScreenshotCrawlResult` 内部新增 `List<String> uploadedKeys`（仅作内部传递，不对外暴露为新 MQ 字段）。

在每处 `s3Service.uploadScreenshotBytes(key, ...)` 调用后，将 `key` 加入 `uploadedKeys`：

```java
List<String> uploadedKeys = new ArrayList<>();

// 上传 index.html
s3Service.uploadScreenshotBytes(s3DirKey + "index.html", ...);
uploadedKeys.add(s3DirKey + "index.html");

// 上传每条 asset
s3Service.uploadScreenshotBytes(s3DirKey + "assets/" + localName, ...);
uploadedKeys.add(s3DirKey + "assets/" + localName);

// 上传 resources.tsv
s3Service.uploadScreenshotBytes(s3DirKey + "resources.tsv", ...);
uploadedKeys.add(s3DirKey + "resources.tsv");

// Phase2（受开关控制）
s3Service.uploadScreenshotBytes(vpPrefix + "screenshot.png", ...);
uploadedKeys.add(vpPrefix + "screenshot.png");
// annotated_screenshot.png / clickable_elements.json 同理
```

需收集的上传点（共 4 类）：
- `s3DirKey + "index.html"`
- `s3DirKey + "resources.tsv"`
- `s3DirKey + "assets/" + localName`（每条资源，body 非空时）
- `s3DirKey + "viewport_" + idx + "/" + 文件名`（Phase2，受开关控制）

#### 改动点 2：ScreenshotService.buildResultMessage — 序列化为 JSON 写入 s3DirKey

```java
// List<String> 序列化为 JSON 数组字符串，写入 s3DirKey 字段
List<String> uploadedKeys = crawlResult.getUploadedKeys();
if (uploadedKeys != null && !uploadedKeys.isEmpty()) {
    message.setS3DirKey(OBJECT_MAPPER.writeValueAsString(uploadedKeys));
} else {
    message.setS3DirKey("[]");
}
```

存储格式示例：
```json
["screenshot/20260526/xxx/index.html","screenshot/20260526/xxx/resources.tsv","screenshot/20260526/xxx/assets/home-individuals-p-500.avif"]
```

**下游兼容说明**：下游原先将 `s3DirKey` 作为目录前缀拼接固定文件名，改造后需将 `s3DirKey` 反序列化为 `List<String>`，直接按路径 `GetObject`，无需 `ListObjects` 扫描目录。下游侧另行评估改造时序。

### 3.6 Phase2 灰度开关

**背景**：Phase2 包含截图（`screenshot.png`、`annotated_screenshot.png`）和 JS 框选交互元素（`clickable_elements.json`）两部分，耗时较长。需要通过灰度开关验证关闭后对吞吐量的提升效果，为后续功能裁剪提供数据支撑。

**改动文件：`ScreenshotPlaywrightService.java`**

新增一个 Lion 开关：

| 配置 Key | 类型 | 默认值 | 说明 |
|---------|------|--------|------|
| `screenshot_phase2_enabled` | Boolean | true | Phase2 整体开关，false 时整个 Phase2 全部不执行 |

**关闭逻辑：**

```
screenshot_phase2_enabled = false：
    → 跳过视口参数采样（sampleViewport / sampleDpr / sampleNumViewports）
    → 跳过截图（screenshot.png）
    → 跳过 JS 元素框选（clickable_elements.json）
    → 跳过标注截图生成（annotated_screenshot.png）
    → s3DirKey 下无任何 viewport_* 目录文件
```

**目的：** 通过关闭 Phase2 后 S3 目录文件数变化和 CAT 耗时指标，对比吞吐收益，验证是否可永久裁剪。

## 八、迭代范围边界

- 不新增任何对外 MQ 字段，`s3DirKey` 字段名不变，只改写入内容（目录前缀字符串 → 文件路径 JSON 数组字符串）
- `ScreenshotResultMessage`、`S3Service` 签名不变；`ScreenshotCrawlResult` 内部新增 `uploadedKeys` 仅用于链路内传递，不透出到 MQ
- 下游需配合改造：将 `s3DirKey` 反序列化为 `List<String>`，直接按路径 `GetObject`，替代原有 `ListObjects` 扫描目录
- 不涉及代理逻辑、线程池、Consumer 层改动
