## 问题一：CSS 二级资源（字体文件）未被下载

### 现象
- CSS 文件（一级资源）已被正确下载并收录到 resources.tsv
- 但 CSS 中通过 `@font-face` 引用的字体文件（`.woff` / `.ttf` / `.woff2` 等）缺失
- 具体表现：
  - sample 1：`font-awesome.css` 已下载，但图标字体的实际字体文件（`FontAwesome.woff` 等）未收录，导致 `<i class="fa fa-angle-down">` 箭头图标和 print icon 无法正常渲染
  - sample 4：Instagram、LinkedIn 的 Font Awesome 图标字体缺失

### 根因分析

**直接原因 1（资源类型 abort）：**
`ScreenshotPlaywrightService.java` 的 Phase1 资源收集阶段（第 427-438 行），`onResponse` 监听器只收集 `javascript`、`css`、`image` 三种 content-type 的响应：

```java
// ScreenshotPlaywrightService.java:436
if (contentType.contains("javascript") || contentType.contains("css") || contentType.contains("image")) {
    collectedResponses.add(response);
}
```

字体文件的 content-type 是 `font/woff2`、`font/woff`、`application/x-font-ttf` 等，**不在收集条件中**，因此完全被跳过，不会出现在 resources.tsv。

**备注（排除项）：**
`ReqSuffixBlackList.java` 中的 `FILE_CONTENT_TYPES` 黑名单（包含 `application/x-font-ttf`）**与 screenshot 无关**。该黑名单仅在 `Downloader.java:313` 中被使用，用于判断主页面 URL 的 content-type 是否是文件类型（非 HTML 页面），与截图资源收集链路完全隔离。

**根本原因（CSS 二级资源不递归解析）：**
当前抓取链路仅收集页面直接触发的网络响应（`onResponse`），不对 CSS 文件内容进行解析提取二级依赖（如 `@font-face` 声明的字体 URL）。字体文件是通过浏览器渲染引擎解析 CSS 后触发的二级请求，如果浏览器在无头模式下因性能优化而延迟加载（或因字体尚未在视口中使用而未实际请求），则这些请求不会出现在 `onResponse` 事件流中。

### 解决方案（已在问题描述中确认）

**字体文件采用在线联网请求策略：**
- Font Awesome、Google Fonts 等主流字体文件内容永远不变，具有很强的可复现性
- 在离线渲染时，对 CSS 文件中的 `@font-face` 规则进行解析，提取字体 URL
- 字体文件通过在线联网请求获取，不依赖抓取时的 snapshot
- 这样既保持了其他资源（CSS/JS）的离线闭环算法，又解决了字体渲染问题

## 问题二：部分图片未被下载（resources.tsv 和 assets 中均缺失）

### 现象
- sample 1 右下角 logo：`guam-map-img.png` 和 `otech_guam_badge_1.png` 缺失（一个在视口范围内，一个不在）
- sample 4：`professor-marseille-scented-5l_8066.png` 等图片缺失（不在视口范围内；同类型在视口内的图片正常）
- sample 7：`front-streetside-view` 缺失（在视口范围内）

### 根因分析

**排除项（PlaywrightService 路由拦截与 screenshot 无关）：**

`PlaywrightService.java` 的路由拦截器会 `abort()` 所有 `image/media` 请求，但这是**普通爬虫路径**的逻辑。`ScreenshotPlaywrightService.java` 完全独立，内部没有设置任何路由拦截，图片请求不会被 abort。

**直接原因 2（图片懒加载，不在视口内未触发网络请求）：**

页面中大量图片使用懒加载（`loading="lazy"` 或 JS 控制），只有滚动到视口范围内时才触发实际的网络请求。在 Phase1 阶段：
- 页面 navigate 后只 `waitForTimeout(3000)` 等待 3 秒（第 449 行）
- 页面停留在初始位置（未滚动）
- 视口外的懒加载图片 **不会发出网络请求**，因此不会被 `onResponse` 捕获

sample 4 中"不在视口范围内的图片缺失，同类型在视口内的图片正常"正好印证了这一点。

**直接原因 3（图片 URL 为背景图，非 `<img>` 标签）：**

部分图片通过 CSS `background-image` 属性引用，其请求行为和触发时机与 `<img>` 标签不同，也更容易受懒加载影响。

**关于 `--disable-images` 标志（排除项）：**

`PlaywrightDownLoader.java:105` 确实带有 `--disable-images`，`ScreenshotPlaywrightService` 也复用了同一个 `PlaywrightDownLoader` 构造方法。但这**不是**图片缺失的原因。

反证：如果 `--disable-images` 真的禁止了所有图片，那已经正常下载的图片（同一页面中视口内的同类图片）也不会存在。实际上部分图片是能被收集到的，说明该 flag 并没有完全阻断图片请求（`--disable-images` 是 Chrome 的内部实验性 flag，在 Chromium headless 模式下实际上**不生效**，或仅影响图片渲染显示而非网络请求本身）。

### 原因优先级汇总

| 原因 | 影响范围 | 可能性 |
|------|---------|--------|
| `--disable-images` 禁用图片加载 | 所有图片 | **高**（解释了视口内图片也缺失的 sample 7） |
| 懒加载导致视口外图片不触发请求 | 视口外图片 | **高**（解释了 sample 4 规律） |
| CSS background-image 触发时机 | 部分图片 | 中 |

## 问题三：视口信息未保存，离线无法复现截图具体位置

### 现象
- 截图时的视口参数（宽度、高度、DPR、滚动坐标）没有被持久化保存
- 离线复现时无法精确还原截图对应页面的哪个位置

### 已知的前置问题
- **离线/在线渲染网页尺寸不一致**：页面 scroll 尺寸在不同环境下可能存在差异，导致 viewport 对应的实际内容区域不同
- 因此，即便保存了视口参数，离线渲染的截图位置可能与在线不一致

### 根因分析

**当前状态（代码层面）：**

截图服务（`ScreenshotPlaywrightService.java` 第 592-596 行）的 `ViewportResult` 仅保存了 `scrollX`、`scrollY`、`elementsJson`，并**没有保存视口的宽高和 DPR**：

```java
// ScreenshotPlaywrightService.java:592-596
viewportResults.add(ScreenshotCrawlResult.ViewportResult.builder()
        .scrollX(scrollX)
        .scrollY(scrollY)
        .elementsJson(elementsJson)
        .build());
```

`viewportWidth`、`viewportHeight`、`deviceScaleFactor`、`numViewports`、`pageWidth`、`pageHeight` 等参数都没有被存入结果中。

**深层原因（架构决策层面）：**

根据讨论中的结论，当前存在以下架构层面的未解决问题：

1. **在线/离线渲染尺寸不一致**：由于字体、CSS 渲染差异，页面 scroll 高度在不同环境可能不同，导致相同的 scrollX/scrollY 对应的内容区域不同
2. **网页 GUI 数据合成细节未解决**：截图与元素信息的关联合成方式尚未最终确定
3. **职责划分未明确**：抓取阶段"截图"和"提取元素信息"是否应该分开

### 当前决策（已确认的方向）

**抓取时不截图，只保存网页完整信息；截图和提取元素信息留到离线在 AIDATA 平台处理。**

具体原则：
- 抓取阶段：只保存 HTML + 静态资源（CSS/JS/图片），不做截图
- 离线阶段：在 AIDATA 平台用统一的浏览器环境复现渲染，再执行截图和元素提取
- 好处：离线环境可控，尺寸一致性可保证；元素提取策略可以独立迭代优化

## 三个问题关联关系总结

```
问题根源树
├── 问题一：字体缺失
│   ├── onResponse 只收集 js/css/image，未包含 font/* content-type
│   ├── ReqSuffixBlackList 将 application/x-font-ttf 列为黑名单
│   └── 抓取链路不递归解析 CSS 的 @font-face 二级依赖
│
├── 问题二：图片缺失
│   ├── --disable-images Chrome 启动参数禁用所有图片加载（主因）
│   ├── 懒加载图片不在视口内不触发请求（视口外缺失的主因）
│   └── 背景图 CSS 触发时机差异
│
└── 问题三：视口信息缺失
    ├── ViewportResult 未保存 width/height/dpr 等参数
    ├── 前置问题：在线/离线渲染尺寸不一致
    └── 架构决策：截图和元素提取移到离线 AIDATA 平台处理
```
