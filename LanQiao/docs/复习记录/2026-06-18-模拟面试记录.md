### 我的回答

### ✅ 完整参考答

if (state == OPEN && now > openTimestamp + openDurationMs) {
    if (stateRef.compareAndSet(OPEN, HALF_OPEN)) {

    }
}
return fallback(); // CAS失败→走备用

## Q126：Redis+Lua令牌桶原理深挖

### 原题
> 三级限流中的Redis令牌桶核心原理是什么？为什么用Lua脚本？

### 我的回答
封装在rhino组件，Redis+Lua实现令牌桶。记录令牌生成速度、上次访问时间、本次申请数量；根据时间差×速率计算补充令牌→比对申请量→放行/拦截→更新存量。用Lua是因为查询令牌数+修改令牌数是两步操作，get+set不是原子的有竞态，Lua实现原子化避免中间态不一致。

### STAR/技术评分
- 令牌桶五步流程 ✅
- Lua原子性理由到位 ✅
- 缺：令牌桶 vs 滑动窗口选型理由 ⚠️
- 缺：为什么不用MULTI/EXEC事务 ⚠️
- 缺：Lua参数约定（KEYS/ARGV）⚠️

### ✅ 完整参考答
**原理**：记录三个字段：令牌速率、上次访问时间戳、当前存量。每次请求：`补充量 = (当前时间 - 上次时间) × 速率`，存量 = min(存量+补充量, 桶容量)；存量≥申请量则放行并扣减，否则拒绝。

**为什么Lua而不是MULTI/EXEC**：MULTI/EXEC基于WATCH实现乐观锁，并发下WATCH失败率高，大量事务重试反而放大Redis压力；Lua脚本在服务端原子执行，无重试开销，性能更稳定。

**为什么令牌桶而不是滑动窗口**：令牌桶允许低峰期积累令牌，容忍短时突发流量；滑动窗口是硬卡QPS，突发请求直接拒绝，用户体验较差。业务上链接抓取有阵发性高峰，令牌桶更合适。

**参数约定**：`KEYS[1]`=桶key，`ARGV`=`[当前时间戳, 申请令牌数, 速率, 桶容量]`，全部参数化避免硬编码。

## Q128：SynchronousQueue选型理由（重训）

### 背景
小红书一面中此题卡顿6分钟，面试官反复追问未答清楚。本题为针对性重训。

### 原题
> 线程池任务队列有三种：无界、有界、SynchronousQueue零缓冲。为什么选零缓冲？有缓冲不是更能抗波峰吗？

### 我的回答（重训版）
无界OOM直接排除；有界队列在MQ面前意义不大——设小马上满走淘汰，设大浪费内存，而且MQ已经是持久化缓冲，不担心丢消息；所以缓冲职责交给MQ，线程池用SynchronousQueue配合while背压：线程池满了主线程sleep，不再拉MQ消息，波峰压力回压到MQ消化。

### 评分
- 无界排除理由 ✅
- MQ=持久化缓冲区核心洞察 ✅
- while+sleep背压传导 ✅
- 表达顺序：结论放最后，建议改为结论先行 ⚠️

### ✅ 黄金话术（结论先行版）
选SynchronousQueue是因为MQ本身就是持久化缓冲区，线程池内部不需要再加一层缓冲。无界队列直接OOM排除；有界队列在MQ面前没意义——设小了马上满，设大了浪费内存，两种情况都不如把缓冲职责交给MQ。SynchronousQueue配合while轮询实现背压：线程池满了主线程sleep，不再从MQ拉消息，波峰压力自然回压到MQ消化。

## Q133：synchronized vs ReentrantLock

### 原题
> synchronized加方法和加代码块区别？你用的哪种？改用ReentrantLock有什么优势？

### 我的回答
方法上锁整个方法，锁对象是方法实例；代码块锁指定对象。我用代码块锁线程池对象，保证检查+提交串行，防止并发同时提交导致线程池打满。ReentrantLock优势：可设公平/非公平锁。

### 评分
- 代码块 vs 方法区别 ✅
- 业务场景理由 ✅
- 公平锁 ✅
- 缺：synchronized方法锁的是`this`（非static）或`ClassName.class`（static），说"方法实例"不准确 ⚠️
- 缺：ReentrantLock另外三个优势未提 ❌

### ✅ ReentrantLock核心优势（四个）
1. **公平/非公平可配置**（synchronized只有非公平）
2. **tryLock(timeout)**：拿不到锁直接返回false，不死等；本场景用tryLock失败走sleep比死等锁更合理
3. **lockInterruptibly()**：等锁期间可响应中断（synchronized不可）
4. **多个Condition**：可以有多个等待队列（synchronized只有一个wait/notify）

### synchronized锁对象规则
- 普通方法：锁`this`（当前实例）
- 静态方法：锁`ClassName.class`（类对象）
- 代码块：锁指定对象
