## 二、失误与薄弱点分析

### 2.1 项目描述被打断——没说清 Sitemap 发现是干什么的

**面试官打断：** 「你在美团做这个是干什么的？」（对 Sitemap 发现的业务价值没听懂）

**候选人的问题：**
> 「负责就是抓取的哪些链接，它是一部分的这个链接来源。」
- 解释太技术化，面试官问的是业务价值，不是技术细节
- 应该先说「做什么」再说「怎么做」

**更好的一句话解释：**
```
我们组是给大模型训练搭建预训练语料库。
我负责其中「链接发现」环节的一条支路：
通过解析网站的 robots.txt 和 Sitemap 文件，批量获取网站收录的 URL，
把这些 URL 灌入链接库，供后续爬虫抓取网页正文。
简单理解：我做的是「告诉爬虫去哪里抓」，而不是「抓内容」本身。
```

### 2.2 频度调度策略讲解——逻辑混乱，重复啰嗦

**面试官问：** 介绍一下你的频度调度策略。

**候选人的问题：**
- 讲了很长，但逻辑层次不清晰（先讲一期的缺陷，再绕回来讲二期，中间穿插留存率计算）
- 「留存率」「规模评分」两个概念没有先定义就使用，面试官很难跟上

**更清晰的讲解结构：**
```
【频度调度策略】——先说背景，再说方案，最后说结果

背景：希望对高频更新站点增加抓取频率，低频站点降低频率，最大化链接发现效益。

一期方案：以「前一天新链产出量」为唯一指标，按天调度。
缺陷：①指标单一，②调度粒度是天，无法覆盖小时级高频更新站点。

二期方案：三维打分模型
  维度1（0.5权重）：新链产出量（当天发现了多少新URL）
  维度2（0.5×0.5权重）：留存率（投递给下游后被留存的比例，反映链接质量）
  维度3（0.5×0.5权重）：规模评分（按站点体量分级，防止小站留存率虚高）

结果：上线后日产出从百亿级显著提升，高频优质站点召回率明显改善。
```

### 2.3 Redis 数据结构题——答得不够完整

**面试官问：** Redis 有哪些常用数据结构？

**候选人的问题：** 没有录音完整记录，但根据后续追问判断，对某些结构的使用场景说得不够精准。

**标准回答：**
```
String：缓存、计数器、分布式锁（SET NX PX）
Hash：存对象字段（比 JSON 序列化省空间，支持单字段修改）
List：消息队列（LPUSH/BRPOP）、最新N条记录
Set：去重、标签系统、交集/并集运算
ZSet：排行榜、延迟队列、滑动窗口限流（按时间戳作为score）
HyperLogLog：近似去重计数（误差0.81%，内存极小）
Bitmap：用户签到、布隆过滤器
Stream：消息队列（支持消费者组，比List更强）
```

### 2.4 HashMap 原理——线程安全性没说清

**面试官追问：** HashMap 为什么线程不安全？

**候选人的问题：** 根据上下文推断，停顿较长，回答不够系统。

**完整回答：**
```
JDK7：并发扩容时，头插法会造成链表成环，导致 get() 死循环
JDK8：改为尾插法，消除了死循环，但仍有以下问题：
  1. put() 非原子操作：判断是否为null → 计算hash → 写入，中间可能被抢占，导致数据覆盖
  2. size++ 非原子操作，可能丢失计数
  3. 扩容时可能读到旧数据

线程安全替代方案：
  - ConcurrentHashMap：JDK8 使用 CAS + synchronized 分段锁，锁粒度是 Node 级别
  - Collections.synchronizedMap()：全局锁，性能差
```

### 2.5 算法题——二叉树序列化

**面试官问：** 实现二叉树的序列化与反序列化。

**候选人的问题：**
- 思路基本正确（BFS层序遍历），但编码过程中写了很久，有些细节不熟练
- 反序列化逻辑（用队列还原父子关系）写得比较生疏

**标准实现（BFS）：**
```java
// 序列化
public String serialize(TreeNode root) {
    if (root == null) return "null";
    StringBuilder sb = new StringBuilder();
    Queue<TreeNode> q = new LinkedList<>();
    q.offer(root);
    while (!q.isEmpty()) {
        TreeNode node = q.poll();
        if (node == null) {
            sb.append("null,");
        } else {
            sb.append(node.val).append(",");
            q.offer(node.left);
            q.offer(node.right);
        }
    }
    return sb.toString();
}

// 反序列化
public TreeNode deserialize(String data) {
    String[] vals = data.split(",");
    if (vals[0].equals("null")) return null;
    TreeNode root = new TreeNode(Integer.parseInt(vals[0]));
    Queue<TreeNode> q = new LinkedList<>();
    q.offer(root);
    int i = 1;
    while (!q.isEmpty() && i < vals.length) {
        TreeNode node = q.poll();
        if (!vals[i].equals("null")) {
            node.left = new TreeNode(Integer.parseInt(vals[i]));
            q.offer(node.left);
        }
        i++;
        if (i < vals.length && !vals[i].equals("null")) {
            node.right = new TreeNode(Integer.parseInt(vals[i]));
            q.offer(node.right);
        }
        i++;
    }
    return root;
}
```
