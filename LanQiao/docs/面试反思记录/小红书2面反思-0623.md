## 二、答得好的地方

### ✅ 项目架构描述层次清晰
自我介绍时把美团 Sitemap 所在整个大环路（调度册 → 抓取册 → 正文抽取 → 链接清洗 → link cache）描述得层次分明，能清楚说明自己负责的模块在全链路中的位置（"在环路之外的一个单独模块"），展示了整体视野。

### ✅ 并发重构亮点描述有细节、有数据
- 原来单线程，IO 等待 10-15 秒，每分钟仅处理约 4 条链接
- 引入线程池，核心线程数=最大线程数，零缓冲同步队列，抛异常拒绝策略
- 用 while+sleep 轮询线程池状态，意识到竞态问题，加了 synchronized 锁
- Kafka 消费分区从 100 扩到 490
- 量化收益：每小时产出从 2-3 万提升到约 90 万，每天新链接产出从 2000-3000 万提升到 52 亿+

面试官没有追问这一块，说明基本满意。

### ✅ 频度调度三维打分体系描述完整
主动讲出 V1 版本的局限性（天级感知、打压过于严格），以及 V2 版本的三维打分（新链接分、质量/留存分、规模分），并举出大站点极端 case（留存率 1% 但链接贡献大）解释为什么需要规模分。"方案迭代思维 + 边界 case 意识"是加分项。

### ✅ 反问环节质量高
连问4个有深度的问题，尤其是"您日常工作中有哪些 AI 使用经验？"引起面试官积极响应，分享了大量 context 建设理念，展示了候选人对 AI 领域的关注和与面试官建立共鸣的能力。

## 三、答得不好的地方（失分点）

### ❌ 失分点1（重大）：无法回答"业界是怎么做的"

**面试官问了什么**：Sitemap 这件事是不是业界通用方案？有没有开源实现？你的设计相对业界有什么不一样？

**候选人答了什么**：
> "相关我没有太理解过行业中的其他实现。"

**为什么严重**：
面试官对这个问题追问了整整 4 分钟（至少 3 次追问），明确表达了他的核心考察意图。更关键的是，在**反问环节面试官专门点出了这条**：他最看重候选人有 "open 的心态，做一件事前先了解业界怎么做，才能做出差异化的判断"——这形成了前后呼应，说明这是这场面试中面试官心里的一根刺。

**标准答法**：
> "Sitemap 协议本身是 sitemaps.org 制定的行业标准，Google、Bing 等主流搜索引擎都遵循这套协议进行链接发现。开源框架中，Apache Nutch 内置了 Sitemap 解析器，Scrapy 有 SitemapSpider 内置支持。我们和这些方案的主要差异在规模——需要处理亿级站点，所以引入了 MQ 做异步解耦、布隆过滤做去重、打压限流防止打崩小站点，这些是通用方案里没有的工程化增强。"

---

### ❌ 失分点2（中等）：RAG 分块策略参数说不清楚

**面试官问了什么**：文档分块时，分段大小怎么控制？

**候选人答了什么**：回答了按语义（段落/句号）切分，但具体数值支支吾吾，说明没有深入做过这块，对实际参数没有印象。

**标准答法**：
> "使用 RecursiveCharacterTextSplitter，chunk_size 设置为 512 tokens，overlap 设置为 50 tokens。选 512 是权衡了语义完整性和召回噪音：太长召回时引入不相关内容，太短则语义不完整。overlap 50 是为了保证跨段落信息连续性，避免切断句子造成语义断裂。"

---

### ❌ 失分点3（中等）：RAG 评测指标靠面试官引导才答出

**面试官问了什么**：怎么从指标层面评测 RAG 系统的好坏？

**候选人答了什么**：候选人只说了人工评估（抽样50个文档人工判断），没有主动提系统化量化指标。最终召回率和召准率是面试官自己说出来的，候选人跟着确认。

**标准答法**（应主动说出）：
> "RAG 评测分两层：检索层用 Recall@K（前K个结果是否包含正确文档）和 MRR（平均倒数排名）评估检索质量；生成层用 Answer Faithfulness（答案是否忠于召回内容，防幻觉）和 Answer Relevance（答案是否回答了用户问题）评估生成质量。RAGAS 框架提供了上述指标的完整评测工具链。"

---

### ❌ 失分点4（轻微）：对自己项目核心指标"留存"的定义解释了两次才说清楚

**面试官问了什么**：留存是怎么定义的？

**候选人反应**：第一次回答偏离方向，被面试官打断更正，第二次才说清楚。

对自己项目核心指标定义要能5秒内一句话说清楚：
> "留存率是指我们召回并抓取的网页中，经过下游质量评分后被认定为高质量（文字丰富、有效内容）并进入预训练语料库的比例。"

## 四、面试官风格特点

| 特点 | 描述 |
|------|------|
| **业务/战略思维强** | 对每个模块先问"这个东西是干什么用的""为什么要有这个"，不只看技术细节 |
| **横向比较意识强** | 反复追问"业界是怎么做的？你这个和别人有什么不一样？"，这是他最核心的考察维度 |
| **系统设计 > 八股** | 全场没有出 Java 基础/算法/数据结构题，全是项目深挖和系统设计思路 |
| **不轻易放弃追问** | "业界实现"一个问题追问了至少 3 次，即使候选人给出模糊答案也继续追 |
| **会帮候选人梳理** | 候选人说不清时，面试官会自己总结候选人的意思让其确认，说明在认真倾听 |
| **会直接给出答案** | RAG 指标题候选人答不出时，面试官直接说了召回率和召准率，说明不打算在这道题深究 |

## 五、核心反思 & 下次行动项

### 反思1：做任何设计前要先了解业界实现

这是本场最大的教训。面试官在反问环节直接点出了他最看重的品质：
> **"做一件事情之前，先了解行业上是怎么做的，然后再去思考差异化在哪里。"**

**行动项**：以后介绍任何项目模块时，都要准备一句话说清楚：
- 行业通用方案是什么
- 开源实现有哪些（至少说出 1-2 个名字）
- 我们和它们的差异在哪里（规模？定制化工程？）

### 反思2：RAG 项目要深入到参数级别

RAG 项目是个人项目，这是候选人可以主动拿分的地方，但分块 chunk_size、overlap、评测指标这些细节答得很浅。

**行动项**：
- 熟记：chunk_size=512 tokens，overlap=50，以及选型理由
- 熟记：Recall@K、MRR（检索层）、Faithfulness、Relevance（生成层），以及 RAGAS 框架

### 反思3：项目核心名词要有"10秒标准答案"

自己项目里的每个核心名词、每个核心指标，都要能在10秒内一句话说清楚，不能被追问自己项目的定义时还要想半天。

**行动项**：把以下概念练成10秒标准答案：
- 留存率的定义
- compositeScore 的三个维度及各自含义
- 新链接分的定义
- 三级限流各层的职责

## 六、加分项（可复用的好表现）

- **反问技巧**：问"您日常最大的技术挑战是什么"和"您在 AI 工具上有什么使用心得"是非常好的问法，能让面试官打开话匣子，展示候选人的技术视野和沟通能力。可以在后续每场面试中复用。
- **方案迭代叙述**：先说 V1 的问题，再说 V2 的改进，比直接介绍最终方案更有说服力，面试官看到的是"思考过程"而不只是"结论"。
