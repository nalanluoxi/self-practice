### 2.2 SQL 题写得较慢，LEFT JOIN + NULL 处理不熟

**题目：** Person 和 Address 两表 LEFT JOIN，查询所有 person 的姓名和地址，
地址不存在时显示 NULL（LeetCode 175 题风格）

**候选人的问题：**
- 语法不流畅，停顿较多，写了较长时间
- 对 `IFNULL` / `COALESCE` 的使用不够熟练

**正确写法：**
```sql
SELECT p.firstName, p.lastName, a.city, a.state
FROM Person p
LEFT JOIN Address a ON p.personId = a.personId;
```

**LEFT JOIN 要点：**
```
- LEFT JOIN：保留左表所有行，右表无匹配时填 NULL
- 与 INNER JOIN 的区别：INNER JOIN 只保留两边都有匹配的行
- NULL 处理：IFNULL(a.city, '无') 或 COALESCE(a.city, '无')
- 面试高频变种：
  * 只查没有地址的人：WHERE a.personId IS NULL
  * 统计每人地址数量：GROUP BY + COUNT
```

### 2.3 RAG 向量库构建细节不够清晰

**面试官问：** 向量库是怎么建的？文档如何导入？

**候选人的问题：**
- 只说了「传文件→入库」，没有说分块策略（Chunking）
- 没有提到 Embedding 模型选型

**更好的回答：**
```
向量库构建流程：
1. 文档上传：MD5 去重，避免重复入库
2. 文档解析：Apache Tika 解析 PDF/Word/HTML 等格式
3. 分块（Chunking）：
   - 固定大小分块（如512 token），带重叠（overlap 50 token）保留上下文
   - 或按段落/标题语义分块
4. Embedding：调用 Embedding 模型（如 text-embedding-ada-002）将每块转为向量
5. 存储：向量存入向量库（PgVector/Milvus），原文存入数据库，两者通过 chunkId 关联
6. 异步 + 兜底：入库异步执行，定时任务扫描状态为 PENDING 的记录重试
```
