### 2.1 JAR 包冲突排查——没有说出 Maven 工具

**面试官问：** 发生 JAR 包冲突，你从自身对 Java 生态的理解，排查思路是什么？

**候选人的问题：**
- 排查思路基本靠「回退 + 比对」，没有说出 Maven 相关工具
- 没有提到 `mvn dependency:tree` 查看依赖树，也没有说 `<exclusion>` 排除

**更完整的回答：**
```
1. 确认症状：NoSuchMethodError / ClassNotFoundException / 方法行为异常
2. 定位冲突：
   mvn dependency:tree -Dincludes=groupId:artifactId
   → 找到同一个 jar 被引入了多个版本
3. 分析影响：确认哪个版本包含需要的 API
4. 解决：
   在引入冲突依赖的 <dependency> 中加 <exclusion> 排除低版本
   或在 <dependencyManagement> 中锁定统一版本
5. IDEA 插件：Maven Helper / Dependency Analyzer 可视化查看冲突
```

### 2.2 双亲委派机制——只说了名字没展开

**面试官问：** 了解类加载的双亲委派机制吗？

**候选人：** 「你说的是双亲委派机制是吗？」——反问确认，没有主动展开描述。

**完整回答：**
```
双亲委派流程：
  1. 收到类加载请求，先委托给父类加载器
  2. 父类加载器继续向上委托，直到 Bootstrap ClassLoader
  3. 父类加载器无法加载时，才由当前加载器自己加载

三层 ClassLoader：
  Bootstrap ClassLoader（C++实现，加载 java.lang.* 等核心类）
  Extension ClassLoader（加载 $JAVA_HOME/lib/ext 下的 jar）
  Application ClassLoader（加载 ClassPath 下的应用类）

作用：
  - 保护核心类库不被篡改（用户无法自定义 java.lang.String 替换核心类）
  - 避免同一个类被多次加载（类唯一性由 ClassLoader + 全限定名共同决定）

破坏双亲委派的场景：
  - SPI（JDBC Driver）：父类加载器无法调用子类加载器的实现，用线程上下文类加载器解决
  - Tomcat：每个 Web App 有独立 ClassLoader，实现类隔离
  - OSGi / 热部署：模块化类加载，实现类版本隔离
```

### 2.3 JAR 包热升级——方向对但细节没说出

**面试官问：** 如何在不停服的情况下，实现 JAR 包热升级？已加载的类同名怎么替换？

**候选人表现：** 说出了「重写一个 ClassLoader 扫描新 jar 包」，但无法回答「已加载的同名类如何被替换」，最终「暂时没有思路」。

**正确回答（类隔离 + ClassLoader 替换）：**
```
核心原理：JVM 中类的唯一性 = ClassLoader实例 + 全限定类名
  → 不同 ClassLoader 实例加载同名类，JVM 视为不同的类
  → 不需要"替换"已加载的类，而是用新 ClassLoader 加载新版本

热升级流程：
  1. 将新版 jar 上传到服务器指定目录
  2. 创建新的 URLClassLoader，指向新 jar
       URLClassLoader newLoader = new URLClassLoader(
           new URL[]{newJarUrl}, parentClassLoader);
  3. 用新 ClassLoader 加载目标类，创建新实例
  4. 业务代码通过公共接口/反射调用新实例（接口由 Parent ClassLoader 加载，保证兼容）
  5. 旧 ClassLoader 的引用断开后，JVM GC 回收旧类

注意事项：
  - 公共接口必须由 Parent ClassLoader 加载，新旧版本实现同一接口
  - 需要处理正在处理中的请求（优雅切换：等待旧实例处理完再替换）
  - 静态变量、单例等状态不会自动迁移，需要手动处理

典型应用：Tomcat Web 应用热部署、OSGi、JRebel 热重载
```

### 2.4 算法题——DAG 拓扑排序（理解有偏差）

**面试官题目：** 设计 DAG 数据结构，实现满足「父节点先于子节点打印」的遍历。

**候选人出现的问题：**
1. 一开始误以为每个节点只有一个父节点，被面试官纠正（DAG 支持多父节点）
2. 对「所有节点」的管理方式表达混乱，没有想到用「全局节点集合 + 入度表」
3. 思考时间过长，多次停顿

**正确解法（Kahn 算法 BFS 拓扑排序）：**
```java
class Node {
    String name;
    List<Node> children = new ArrayList<>();
}

public List<String> topologicalSort(List<Node> allNodes) {
    // 1. 计算每个节点的入度
    Map<Node, Integer> inDegree = new HashMap<>();
    for (Node node : allNodes) {
        inDegree.putIfAbsent(node, 0);
        for (Node child : node.children) {
            inDegree.merge(child, 1, Integer::sum);
        }
    }
    // 2. 将所有入度为0的节点（根节点，可能多个）入队
    Queue<Node> queue = new LinkedList<>();
    for (Map.Entry<Node, Integer> e : inDegree.entrySet()) {
        if (e.getValue() == 0) queue.offer(e.getKey());
    }
    // 3. BFS 遍历
    List<String> result = new ArrayList<>();
    while (!queue.isEmpty()) {
        Node cur = queue.poll();
        result.add(cur.name);
        for (Node child : cur.children) {
            // 入度减1，为0时说明所有父节点已打印，可以打印该节点
            if (inDegree.merge(child, -1, Integer::sum) == 0) {
                queue.offer(child);
            }
        }
    }
    return result; // 长度 < allNodes.size() 说明有环
}

// 关键点：
// 1. allNodes 传入所有节点（不只是根节点），才能构建完整入度表
// 2. 根节点可以有多个（入度=0）
// 3. 一个节点可以有多个父节点（入度>1）
```
