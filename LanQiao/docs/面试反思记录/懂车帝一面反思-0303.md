## 二、失误与薄弱点分析

### 2.1 线程池参数设计缺乏原理支撑

**面试官问：** 线程池的核心线程数是怎么设置的？为什么是 10？

**候选人的问题：**
> 「记得当初好像是 10 个核心线程」「最开始设计的时候是...」
- 只说了结果（10个），完全没有解释为什么，显得是拍脑袋决定的
- 没有提到 IO 密集型 vs CPU 密集型线程池的区别和公式

**更好的回答：**
```
由于抓取是 IO 密集型操作（网络请求等待），线程池核心线程数设置参考公式：
  核心线程数 = CPU核数 × (1 + 等待时间/计算时间)
当时一条请求约10~15秒，其中网络IO等待占90%，
所以实际配置是：核心线程数较大（如50+），配合有界阻塞队列防止内存溢出。
初始从10开始灰度，通过监控线程池活跃数和队列积压动态调整到合适值。
```

### 2.2 Kafka/Mafka 扩容细节说不清楚

**面试官问：** 从 200 台扩到 400 台，依据是什么？

**候选人的问题：**

- 没有说明扩容的触发指标是什么（积压量/消费延迟）
- 没有说明扩容时 Partition 数量如何调整

**更好的回答：**
```
扩容依据是消息队列积压监控：当积压量持续超过阈值X条、消费延迟超过Y秒时触发。
Mafka集群从200扩到400台，同时将Topic的Partition数量从N翻倍到2N，
让新增的消费者实例能均匀消费，避免扩容后机器空闲。
```

### 2.3 Java 类加载机制——双亲委派只说了概念没展开

**面试官问：** 知道双亲委派机制吗？

**候选人的问题：**
> 「你说的是双亲委派机制是吗？」——反问确认，没有主动展开描述
- 只确认了名字，没有说清楚双亲委派的流程和作用

**正确完整的回答：**
```
双亲委派机制：
1. 类加载请求先委托给父类加载器，父类无法加载时才由自己加载
2. 加载顺序：Bootstrap ClassLoader → Extension ClassLoader → Application ClassLoader
3. 作用：
   - 保证核心类库（java.lang.*）不被篡改
   - 避免同一个类被多次加载，保证类的唯一性
4. 破坏双亲委派的场景：
   - SPI机制（JDBC驱动）：需要父类加载器加载子类加载器的实现，用线程上下文类加载器解决
   - OSGi / Tomcat：各模块独立类加载器，实现类隔离
```

### 2.4 热升级/类隔离问题——完全不会

**面试官问：** 如何在不停服的情况下，用类加载器实现 jar 包热升级？

**候选人的表现：**
> 思考了约1分钟，给出了「重写一个类加载器去扫描新 jar 包」的方向，但无法解释「如何替换已加载的类」

**面试官进一步追问：** 类名相同，正常类加载器不会重复加载，怎么办？

**候选人：** 「暂时没有思路」

**正确回答：**
```
热升级核心思路：用全新的 ClassLoader 实例加载新版本 jar
1. 每个版本的 jar 使用独立的 URLClassLoader 实例加载
   - 因为类的唯一性 = ClassLoader实例 + 全限定类名
   - 不同 ClassLoader 实例加载同名类，JVM认为是不同的类
2. 热升级流程：
   a. 将新版本 jar 上传到指定路径
   b. 创建新的 URLClassLoader，指向新 jar
   c. 用新 ClassLoader 加载目标类，创建新实例
   d. 通过接口/反射调用新实例（新旧版本实现同一接口）
   e. 旧 ClassLoader 引用断开后，JVM GC 回收旧类
3. 注意事项：
   - 新旧接口必须兼容，通过 Parent ClassLoader 加载公共接口
   - 需要处理线程正在使用旧实例的情况（优雅切换）
典型应用：Tomcat 类加载机制、OSGi 框架、热部署框架（如 JRebel）
```

### 2.5 算法题——DAG 拓扑排序

**面试官问：** 设计数据结构存储 DAG，并实现满足约束（父节点先于子节点打印）的遍历。

**候选人的问题：**
1. **前期理解有偏差**：误以为每个节点只有一个父节点（其实 DAG 允许多父节点），被面试官纠正后才调整思路
2. **数据结构设计模糊**：一开始说「做成一个 map 的映射」，但没有说清楚具体是什么结构
3. **思考时间过长**：多次停顿超过30秒，在面试中表现为反应慢

**正确解法（拓扑排序 BFS/Kahn 算法）：**
```java
// 数据结构设计
class Node {
    String name;
    List<Node> children; // 子节点列表
    // 不需要存父节点引用，用入度表代替
}

// 算法：Kahn 算法（BFS 拓扑排序）
public List<String> topologicalSort(List<Node> allNodes) {
    // 1. 计算每个节点的入度
    Map<Node, Integer> inDegree = new HashMap<>();
    for (Node node : allNodes) {
        inDegree.putIfAbsent(node, 0);
        for (Node child : node.children) {
            inDegree.merge(child, 1, Integer::sum);
        }
    }
    // 2. 将所有入度为0的节点入队（根节点，可能多个）
    Queue<Node> queue = new LinkedList<>();
    for (Map.Entry<Node, Integer> entry : inDegree.entrySet()) {
        if (entry.getValue() == 0) queue.offer(entry.getKey());
    }
    // 3. BFS 遍历
    List<String> result = new ArrayList<>();
    while (!queue.isEmpty()) {
        Node cur = queue.poll();
        result.add(cur.name); // 打印
        for (Node child : cur.children) {
            if (inDegree.merge(child, -1, Integer::sum) == 0) {
                queue.offer(child); // 入度变0，可以打印
            }
        }
    }
    return result;
}
```
