多线程并发重构与消息队列扩容｜原系统单线程消费 Mafka，单次同步耗时约 15s。重构为回调线程 + 业务线程池异步并行模型，SynchronousQueue 无缓冲队列天然背压防堆积，线程池满时主线程自旋等待保证消息不丢；同步将 Mafka 从 200 分区扩容至 400 分区消除传输瓶颈。小时抓取量从 2.5 万升至 96 万+，日均新链发现量最高达 75 亿。

三级限流 + 动态自适应限流体系建设｜Sitemap 环路大站挤兑小站，固定阈值无法感知线程池负载。限流侧三级递进：集群层与单机层 Rhino 保护下游，站点层自实现滑动窗口限流器（ConcurrentSkipListMap 按毫秒粒度记录时间片请求数）精确限频，无效流量前置拦截。自适应侧 Daemon 线程每秒采样健康度（activeCount/corePoolSize），环形缓冲连续 3 次越过 80% 水位触发配额收缩，避免频繁调整线程池大小的抖动。调度产出从集中双峰优化为全天均匀，峰值 QPS 达 1417+。

GZIP 压缩 Sitemap 解析能力补齐｜原链路对 .gz 格式直接丢弃，日志打点发现日均 400 万+ 新链流失。利用 GZIPInputStream 流式解压，字节数组经 ByteArrayInputStream → GZIPInputStream → 1KB 缓冲循环读取转 UTF-8，无缝接入原有解析链路。推全后新链发现量从 3.79 亿激增至 52.6 亿，14 倍产出增长。

站点频度调度策略建设｜原方案每日固定全量调度，高频站点遗漏新链，低频站点白占资源。设计三维打分（新链接分 + 留存率分 + 规模分）加权为 compositeScore，划分 5 级平滑降级；抓取侧 Redis TTL 差异化控制重复抓取间隔，多定时任务支持一天多轮投递。sitemap 日新链产出从 10~70 亿提升至 100~200 亿（约 10 倍）。

DSL 规则引擎治理垃圾/作弊站点｜人工质检发现大量参数爆炸、路径随机等作弊站点混入链路。@PostConstruct 阶段正则一次性预编译缓存至 HashSet，@MdpConfigListener 监听配置变更自动重编译秒级热更新，拦截逻辑前置于所有资源消耗操作之前。抽样高质量站点率从 4.1% 提升至 11.9%。

HTML 数据合成链路独立主导搭建（v1 → v2）｜从零搭建多模态训练数据生产服务（Mafka 消费 → Playwright 抓取 → S3 上传 → 结果 MQ），在搭建和迭代过程中遇到并攻克以下问题：

①【两次 navigate 浪费资源 + 内存峰值高】v1 Phase1/Phase2 各起一次页面加载，重复浪费 50% 网络请求；onResponse 字节全量持有内存峰值高。解法：合并为一次 navigate(LOAD) + 单 BrowserContext；onResponse 取字节后立即上传 S3 置 null 释放；新增两层隔离线程池（DOWNLOAD_TASK_POOL + SUPPLEMENT_POOL）防止内部提交死锁。

②【字体缺失导致离线渲染乱码】Chrome 懒加载机制下未触发的字体请求 onResponse 无法捕获。解法：supplementFontsFromCss() 用 helger/ph-css 解析 CSS 中所有 @font-face src 声明，主动下载 Chrome 未触发的字体文件，以 collectedFontUrls Set 去重避免重复下载。

③【懒加载图片大量缺失】IntersectionObserver 懒加载图片只有进入视口才发请求，不滚动则 onResponse 仅捕获首屏。解法：Phase1 分步逐视口 scrollTo + 300ms 等待触发全量图片请求；supplementImagesFromHtml() 用 Jsoup 解析 srcset 所有尺寸变体和 data-src 属性，与已收集 URL 取差集兜底遗漏图片。

④【JS/CSS 被 onResponse 遗漏】部分资源因浏览器缓存（304）或跨域限制未捕获响应体。解法：supplementScriptsAndStylesFromHtml() 解析 HTML 中 <script src> / <link rel=stylesheet>，与 collectedJsCssUrls 取差集主动补充下载。

⑤【styled-components 动态样式丢失】styled-components 通过 el.sheet.insertRule() 写 CSSOM 不写 textContent，page.content() 序列化只取 DOM，动态样式全部丢失。解法：注入 JS 将 data-styled style 标签的 cssRules 写回 textContent，再序列化 HTML，确保动态样式落入离线文件。

⑥【下游 S3 ListObjects 成并发瓶颈】v1 结果消息仅携带目录前缀，下游须 ListObjects 扫描文件列表，高并发下触碰 S3 QPS 限制。解法：抓取过程中用 CopyOnWriteArrayList 收集每个文件完整路径，任务结束后序列化为 JSON 数组写入消息，下游直接 GetObject 消除扫描依赖。
