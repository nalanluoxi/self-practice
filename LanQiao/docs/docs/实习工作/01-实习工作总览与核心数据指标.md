## 三、系统整体架构定位

```
【大模型语料抓取系统 - Sitemap 链路全景】

上游（离线调度层 llm-spider-jobs）
├─ RobotsMsgSendingJob         → 每日发送百万级 robots 请求到 MQ
├─ UpdateFrequencyTableJob     → T+1 离线评分，写 DF/DI 表（打分+等级）
└─ FrequencyDeliverySitemapJob → 按 grade 过滤 DF 表，多轮投递到 MQ

↓ Topic: llm_sitemap_url

在线消费层（llm-spider-crawler）
SitemapRequestConsumer
  → 12 道预处理漏斗（去重/限流/正则拦截/时效性检测）
  → SynchronousQueue + ThreadPoolExecutor 并发处理
  → SitemapService.download()
      ├─ robots 分支 → 解析 sitemap URL → 回环发 MQ
      └─ sitemap 分支 → 解析 pageURL → 发 sitemapResultTopic

↓ Topic: sitemapResultTopic

下游（链接库 / 模糊去重 / 质量过滤）
└─ pageURL → linkbase → 调度 → 抓取 → 语料库
```

## 四、关键技术亮点

| 技术点 | 实现方式 | 解决问题 |
|:--|:--|:--|
| 三级限流 | Rhino OneLimiter（集群+单机+站点），站点层以 EffectiveTldFinder 提取顶级域作为 uuid 传入 Rhino | 大站挤兑小站 |
| 自适应限流 | ConcurrentSkipListMap 滑动窗口计数器（CounterRateLimiter）+ 守护线程 80% 水位检测动态调整配额 | 线程池利用率低 |
| 频度调度打分 | `compositeScore = 0.5×newUrlScore + 0.5×(0.5×rateScore + 0.5×scaleScore)` | 资源粗放调度 |
| GZIP 解析 | GZIPInputStream 流式解压 + URL 后缀嗅探 | 压缩格式盲区 |
| 策略拦截 | 正则预编译 + @MdpConfigListener 热更新 + @PostConstruct 缓存 | 作弊站点质量 |
| 时效性过滤 | dispatchTs 与 staleThresholdHours（默认 48h）比对 | 历史积压消息 |
| Playwright 截图 | BrowserContext + 自定义线程池 + 边抓边上传 S3 | 多模态训练需求 |
