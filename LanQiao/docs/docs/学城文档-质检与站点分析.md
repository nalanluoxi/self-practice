## 文档4: Sitemap 频度调度评分优化方案 2.0

- **文档ID**: 2757591191
- **URL**: https://km.sankuai.com/collabpage/2757591191
- **作者**: nalan_luoxi
- **创建时间**: 2026-04-15

### 内容摘要

爬虫每天会抓取大量网站的 Sitemap（网站地图文件），从中发现新链接并投递给爬虫去抓取。

**核心问题**：并不是所有 Sitemap 都值得每天抓——有些网站天天更新（新闻站），有些几乎不更新（小博客），有些是垃圾站点。需要一套机制来判断每个 Sitemap **投递频率的优先级**。

### 一、现状与问题

#### 现有逻辑
记录每个 Sitemap 近 3 天是否产出过新链接（0/1），3 天都有就是高频，都没有就废弃。

#### 现有问题

| 问题 | 举例 |
| --- | --- |
| 信号粗糙，只有 0/1 | 昨天产出 1 条新链接和产出 1000 条，打分一样 |
| 一天只投递一次 | 高质量新闻站中午更新了，但今天已经投过，等到明天才能抓 |
| 未考虑内容质量 | 垃圾站天天有新链接，照样高频投递 |
| 有状态维护成本高 | 每天要更新历史 JSON，出错难排查 |

### 二、新方案整体数据流

```
① SitemapBloomFilterJob（前置改造）
   将 sitemapurl / dispatch_ts 写入新链接表
   ↓
   sitemap_link_bloomfilter_daily_new_url（新链接表，含来源 sitemapurl）

② UpdateFrequencyTableJob（核心打分任务）
   ┌─────────────────────────────────────────────────────┐
   │ Driver 端预加载（Broadcast 广播到所有计算节点）       │
   │ · 黑名单集合（整站拦截）                              │
   │ · 条件过滤集合（特定路径拦截）                        │
   │ · domain 留存打分表（质量 × 规模）                    │
   └─────────────────────────────────────────────────────┘
   ↓
   读昨日新链接表，按 sitemapurl 聚合命中批次数
   ↓
   对每个 sitemapurl 执行打分 UDF：
   ① 黑名单过滤 → 命中 → grade=4（直接淘汰）
   ② 计算综合分 → compositeScore → 映射 grade 1/2/3/4
   ↓
   写入 llm_data_sitemap_frequency_delivery_df（频度 DF 表）

③ FrequencyDeliverySitemapJob（投递任务）
   读 DF 表中 grade=1/2/3 的链接
   每个链接统一投递 → 发送到 MQ → 爬虫消费抓取
```

### 三、打分机制详解

#### 3.1 第一关：黑名单过滤

进入打分前先过两道黑名单，命中直接置 grade=4 不投递：

| 拦截方式 | 数据来源 | 举例 |
| --- | --- | --- |
| **整站拦截**（domain 级） | spider_site_info 中标记为色情/赌博/小说等 | xxx-novel.com 整站拦截 |
| **路径拦截**（pattern 级） | spider_site_info 中标记为工具页/入口页 | example.com/tools/* 只拦截这个路径 |

> 与 DumpLinkPatternFilterJob 使用相同的黑名单表和相同的拦截逻辑，保持一致。

#### 3.2 第二关：综合打分

通过黑名单的 sitemapurl，用两个信号综合打分：

```
compositeScore = 0.5 × newUrlScore + 0.5 × fuzzyScore
```

**信号一：新链接产出分（newUrlScore）**——权重 50%

统计昨天该 Sitemap 在 6 次投递批次中，有几次产出了新链接：

```
newUrlScore = 昨日命中批次数 / 6
```

| 命中情况 | newUrlScore | 举例 |
| --- | --- | --- |
| 6次全中 | 1.0 | 每批次都有新链接 |
| 命中4次 | 0.67 | 一天中大部分时段有更新 |
| 命中2次 | 0.33 | 偶尔有更新 |
| 0次 | 0.0 | 昨天没有任何新链接 |

**信号二：domain 留存质量分（fuzzyScore）**——权重 50%

衡量这个站点的内容"有没有价值"，用两个维度综合评估：

```
fuzzyScore = 0.5 × 留存率分（rateScore） + 0.5 × 规模分（scaleScore）
```

**留存率分**（内容质量）：

| 留存率 | rateScore | 含义 |
| --- | --- | --- |
| ≥ 4% | 1.0 | 投 100 条留 4 条，质量满分 |
| ≥ 2% | 0.75 | 内容质量较好 |
| ≥ 1% | 0.5 | 一般 |
| >0% | 0.25 | 较低 |
| = 0% | 0.0 | 完全无价值，打压 |

**规模分**（产出量）：

| 每日留存条数（save_cnt） | scaleScore | 站点类型 |
| --- | --- | --- |
| ≥ 1000 条 | 1.0 | 大站（满分） |
| ≥ 100 条 | 0.8 | 中大站 |
| ≥ 10 条 | 0.6 | 中小站 |
| ≥ 1 条 | 0.4 | 小站 |
| = 0 条 | 0.0 | 无留存产出 |

> 为什么需要规模分？——防止"小站虚高"：一个小博客投 1 条留 1 条，留存率 100%，但实际对系统没有价值；大新闻站留存率 50% 反而应该高频投递。

**无数据默认值**：domain 当天不在留存表中（新站/数据延迟），默认给 0.35（中等偏下，不惩罚但不倾斜资源）。

#### 3.3 综合分 → 等级映射

**第一步：compositeScore 基础映射**

```
compositeScore ≥ 0.75 → grade 1（HIGH）   投递 6 次/天
compositeScore ≥ 0.50 → grade 2（MIDDLE） 投递 4 次/天
compositeScore ≥ 0.25 → grade 3（LOW）     投递 2 次/天
compositeScore < 0.25 → 进入第二步兜底判断
```

**第二步：rateScore 兜底（防止有内容价值的站被错误淘汰）**

compositeScore < 0.25 时：
- rateScore ≥ 0.1（留存率 ≥ 1%，内容有一定价值）→ 保底 grade 4，投递 1 次/天
- rateScore < 0.1（留存率 < 1%，内容基本无价值）→ 确认 grade 5，等待手动回捞

> **升降级保护**：升级不限速（可直接跳级，快速响应质量提升）；**降级每次最多 -1 级**（防止单次 IO 异常/带宽波动等偶发故障导致优质站点被立即淘汰）。

### 五、投递方式变化

| | 旧方案 | 新方案 |
| --- | --- | --- |
| grade=1 投递次数 | 1次/天 | **6次/天** |
| grade=2 投递次数 | 1次/天 | **4次/天** |
| grade=3 投递次数 | 1次/天 | **2次/天** |
| grade=4 投递次数 | 不投递 | **1次/天（低频保活）** |
| grade=5 | 无此等级 | **不投递，人工处理** |
| 投递时间点分布 | 任务启动时 | 均匀分散在一天内 |

**各 grade 对应的投递时间点**：

| grade | 含义 | 每日投递次数 | 投递时间点 |
| --- | --- | --- | --- |
| 1（HIGH） | 高频更新+高质量 | **6次** | 00:00 / 04:00 / 08:00 / 12:00 / 16:00 / 20:00 |
| 2（MIDDLE） | 中频更新或质量好 | **4次** | 00:00 / 06:00 / 12:00 / 18:00 |
| 3（LOW） | 低频更新或质量一般 | **2次** | 00:00 / 12:00 |
| 4（DISUSE） | 初步废弃，低频保活 | **1次** | 00:00 |
| 5（PENDING） | 黑名单拦截 | **不投递** | DF 表保留，等待人工回捞 |

> grade 越高，一天内被抓取的次数越多，能及时捕捉到站点在不同时段发布的新内容。
