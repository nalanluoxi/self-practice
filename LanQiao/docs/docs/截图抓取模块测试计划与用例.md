# 截图抓取模块测试计划与用例

> 版本：v2.0（适配两阶段 status/errorReason 重构）
> 适用模块：`llm-crawler-server` — Screenshot 截图抓取功能
> 编写时间：2026-05-14

---

## 一、测试目标与范围

本测试计划覆盖截图抓取模块的以下关键能力：

| 序号 | 测试目标 | 说明 |
|------|----------|------|
| T1 | **两阶段异常记录完整性** | phase1/phase2 ErrorReason 在各种失败场景下是否正确填写 |
| T2 | **UA 与代理类型映射** | OVERSEA_NORMAL → Chrome137、OVERSEA_ADVANCED_LINE → Chrome136、MAINLAND_NORMAL → Chrome130 |
| T3 | **ThreadLocal 超时续期清理** | 实例使用超过 PLAYWRIGHT_INSTANCE_SURVIVE_MAX_TIME（5分钟）时自动重建 |
| T4 | **后台清理线程** | Screenshot-Cleanup-Thread 定时扫描 instanceMap，关闭并移除过期实例 |
| T5 | **实例清理机制正确性** | 使用中实例不被误杀，续期机制是否生效，关闭超时强制中断 |
| T6 | **Locale/Timezone 映射** | 不同代理线路设置正确的 locale 和 timezone |
| T7 | **S3 上传与 Redis 去重** | 抓取成功后 S3 写入、Redis 标记、MQ 发送的完整链路 |
| T8 | **消息体大小控制** | html 超过 1MB 压缩、超过 4MB 截断 |

## 六、L4 异常与边界测试

### 6.1 实例清理机制完整验证（T5 核心）

#### TC-42：实例清理机制与 PlaywrightService 对比分析

**当前 ScreenshotPlaywrightService 清理逻辑梳理：**

| 机制 | ScreenshotPlaywrightService | 说明 |
|------|----------------------------|------|
| 存活时间 | `PLAYWRIGHT_INSTANCE_SURVIVE_MAX_TIME = 5分钟` | 固定常量 |
| 过期时间戳存储位置 | `instanceMap<实例, 过期时间戳>` | 每次使用时刷新：`now + timeout + 10000ms` |
| ThreadLocal 检查 | 取 `THREAD_TIME_XXX`，若超过 5 分钟则重建 | 基于"创建/最后重建时间"而非"最后使用时间" |
| 后台清理线程 | 每 5s 扫描 instanceMap，移除 `过期时间戳 <= now` 的实例 | instanceMap 中的过期时间会被每次使用时续期 |

**⚠️ 发现的设计问题：**

1. **ThreadLocal 时间戳与 instanceMap 时间戳语义不同**：
   - `THREAD_TIME_XXX` 记录的是"实例上次重建的时间"
   - `instanceMap.value` 记录的是"实例过期时间"（每次使用续期）
   - 后台清理线程检查的是 instanceMap，而 ThreadLocal 检查的是 THREAD_TIME。两套逻辑可能导致：ThreadLocal 刚重建了新实例，但 instanceMap 中的旧实例早已被清理（实际上在 ThreadLocal 重建时已调用 instanceMap.remove 并关闭旧实例）。

2. **instanceMap 续期逻辑**：每次使用时 `instanceMap.put(instance, now + timeout + 10000)`，这意味着一个**一直在使用的实例**会不断被续期，永远不会被清理线程清理，但 ThreadLocal 检查会在 5 分钟后触发重建（此时 instanceMap 中还有旧实例条目）。实际上重建时会 `instanceMap.remove(old)` 再关闭，所以不会泄漏，但逻辑略绕。

3. **结论**：清理机制整体安全，不会有实例泄漏，但建议验证如下边界。

**测试步骤（需要反射修改常量辅助测试）：**
1. 缩短 `PLAYWRIGHT_INSTANCE_SURVIVE_MAX_TIME` 为 10s（反射修改或测试配置）
2. 创建一个实例，让它持续被使用（每隔 3s 调用一次）
3. 观察 10s 后是否触发 ThreadLocal 重建
4. 同时观察 instanceMap 中旧实例是否被 remove + close

**预期结果**：
- ThreadLocal 检查触发重建，旧实例被 close 并从 instanceMap 移除
- 后台清理线程不会重复 close 已被 ThreadLocal 移除的实例（因为 instanceMap.remove 先于清理线程扫描）

#### TC-43：清理线程不误杀正在使用的实例
- **场景**：实例 instanceMap 过期时间为 `now - 1`，但实例正在被线程执行抓取
- **当前实现**：清理线程不检查"是否正在使用"，直接 close。这是一个**已知风险点**。
- **验证**：构造并发场景，抓取任务进行中，清理线程同时触发
- **预期结果**（记录实际结果）：
  - 若 Playwright 实例被 close 时页面正在加载，会抛出 ContextDestroyedException
  - 该异常应被 Phase1/Phase2 catch 块捕获，写入 phase1ErrorReason 或 phase2ErrorReason
  - 不应导致服务崩溃

**⚠️ 测试结论应输出到问题报告中，评估是否需要加"使用中标记"防止误杀。**
