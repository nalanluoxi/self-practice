================================================================================
             简历版实习工作内容（供挑选，共13点）
================================================================================

团队：美团计算机平台 / FRIDAY组 - LongCat大模型数据团队
岗位：后端开发实习生
方向：大模型预训练语料库建设 / 网页抓取系统 / 多模态截图服务

--------------------------------------------------------------------------------

【1】三级限流防护体系建设
针对Sitemap发现环路大站挤兑小站的顽疾，设计并实现集群层（Rhino OneLimiter）、单机层（均摊策略）、站点层（Redis+Lua令牌桶）三级限流防护网。拦截前置黑名单、URL校验、Redis去重，保护下游基础设施稳定运行。

【2】多线程并发重构，吞吐量提升40倍
将单线程同步消费模式重构为异步线程池架构，采用SynchronousQueue + ThreadPoolExecutor实现消息拉取与业务处理解耦，并引入背压机制防止任务丢失。小时抓取量从2.5万提升至96万+，集群QPS从10提升至400。

【3】自适应流量控制（线程池负载联动限流）
实现"线程池健康度-限流阈值"动态联动模型，后台Daemon线程每秒采样线程池负载，基于80%水位自动扩缩放行配额，避免人工调参滞后。峰值集群QPS达到1417+，全量发现任务时长缩短至3-4小时。

【4】Mafka集群扩容与线程池热更新
通过Lion MDP配置中心实现线程池参数热更新（无需重启），同时推动Mafka集群从200分区扩容至400分区，消除消息传输物理瓶颈。日均新链发现量最高达75亿，英文新链留存量从2000万提升至1.2亿。

【5】GZIP压缩包Sitemap解析能力补齐
发现约4%的Sitemap流量（日均400万+）为.gz压缩格式被直接丢弃，实现GZIPInputStream流式解压并完整对接原有处理链路（Redis去重、限流、CAT监控）。补齐后新链发现量从3.79亿激增至52.6亿（提升14倍）。

【6】频度调度策略与多维打分体系
针对全量站点每日固定调度的资源浪费问题，设计三维打分模型（新链接分+规模分+留存率），并通过Redis TTL差异化控制各频段站点重复抓取间隔，实现高频站点加速、低频站点降载的精细化调度。

【7】DSL规则引擎治理垃圾/作弊站点
基于正则表达式预编译缓存（@PostConstruct阶段）和MDP热更新机制，构建可实时迭代的DSL规则引擎，支持域名级正则匹配与URL指纹特征识别，将拦截逻辑前置于所有资源消耗操作之前。有效拦截90%+垃圾/作弊站点，新规则分钟内上线生效。

【8】Sitemap环路监控体系建设
基于Redis + CAT监控平台，以batchId+小时为粒度构建全链路漏斗监控（robots抓取成功率、URL发现量、sitemap索引量等），替换指标粒度超限的Raptor方案。实现积压/高失败率/无效站点异常的及时发现与告警。

【9】无效站点治理与历史积压清理
通过时间戳过期策略丢弃1500万/天历史积压消息，并将robots失败原因细分持久化（下载失败/默认页/Cloudflare拦截/验证码拦截），采用过期式封禁而非永久屏蔽，兼顾拦截效果与站点恢复能力。

【10】抓取引擎从Selenium迁移至Playwright
主导JS渲染抓取引擎的技术选型与迁移，利用Playwright的BrowserContext实现轻量化多租户隔离（独立Cookie/Cache/Session），配合自定义线程池彻底去除探活/轮询逻辑。代码量大幅精简，高并发场景下资源复用率和抓取效能显著提升。

【11】服务器基础设施治理与自动化运维
解决Playwright线上部署因glibc/gcc版本过低导致高版本Chrome无法运行的问题，推动全量服务器深度版本升级，并将升级流程沉淀为标准化Shell脚本，实现新服务器扩容一键部署。

【12】网页截图抓取全链路服务建设（多模态方向）
面向多模态大模型「看图写代码」训练需求，独立设计截图抓取服务全链路：独立Consumer/线程池/监控指标/Mafka Topic，集成黑名单过滤、URL校验、Playwright渲染截图、S3上传全流程。集群490台机器整体吞吐约1000条/分钟，产出数据用于大模型多模态能力训练。

【13】通搜高优信源监控指标建设
针对通搜场景高优信源的数据质量诉求，基于Hive表设计并落地5类监控指标体系，排查并归因39条异常case，为信源质量闭环提供数据支撑。
