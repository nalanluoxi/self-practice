3. 文档内容包含：
   - 总体目标描述
   - 各模块功能清单
   - 每模块的任务状态（初始均为 `等待`）
   - 已知风险与异常情况说明
4. 交给老大审阅，审阅通过后进入下一阶段

### 第四阶段：任务调度（小银）

老大审阅通过后，**创建子 agent 小银**，负责：

#### 1. 初始化阶段

1. 读取需求策划汇总文档，按模块进行**职责划分**
2. 创建 **`docs/进度/汇总任务进度.md`**，内容包含：
   - 总体目标描述
   - 全部子任务列表（每个子任务：编号、模块名、负责 agent、当前状态、最后更新时间）
   - 全局进度统计（等待 N / 执行中 N / 完成 N / 阻塞 N）
3. 为每个模块在 **`docs/进度/`** 下创建独立**子任务文档**（中文命名），每份文档包含：
   - **任务描述**：模块名、目标、输入/输出、验收标准
   - **完整执行步骤清单**：将任务拆解为有序步骤，每步包含：
     - 步骤编号与描述
     - 状态（`等待` / `执行中` / `完成` / `阻塞`）
     - 执行备注（完成时记录结果摘要，阻塞时记录阻塞原因）
     - 最后更新时间
   - **当前整体状态**：`等待` / `执行中` / `完成` / `阻塞`
   - **断线恢复记录**：记录接管次数、每次接管时间及接管原因
4. 根据模块数量，**动态创建对应数量的临时子 agent**（并行执行）
5. 每个临时子 agent 认领一个子任务，将子任务文档整体状态更新为 `执行中`

#### 2. 子 agent 执行规范

- 启动时**首先读取子任务文档**，确认当前进度，从第一个未完成步骤继续执行（支持断线续跑）
- 每完成一个步骤，立即更新子任务文档中该步骤的状态、备注、更新时间
- 全部步骤完成后：
  - 将子任务文档整体状态标记为 `完成`
  - 通知小银本模块已完成

#### 3. 小银巡检规范

- 小银每隔一段时间**主动读取 `docs/进度/汇总任务进度.md` 及各子任务文档**
- 若发现某子任务满足以下任一条件，判定为异常：
  - 状态长时间停留在 `执行中` 但步骤进度未更新
  - 状态已变为 `阻塞`
- 异常处理流程：
  1. 将该子任务文档整体状态标记为 `阻塞`，记录阻塞原因与时间
  2. 更新 `汇总任务进度.md` 中对应条目状态
  3. 创建**新的临时子 agent** 接管，新 agent 读取子任务文档后从断点继续执行
  4. 在子任务文档的"断线恢复记录"中追加本次接管信息

#### 4. 收尾阶段

- 全部子任务状态均为 `完成` 后：
  1. 小银更新 `汇总任务进度.md` 的全局进度统计为全部完成
  2. 更新**需求策划汇总文档**中各模块任务状态为 `完成`
  3. **询问老大**：`docs/进度/` 下的子任务进度文档及汇总进度文档是否需要删除？
  4. 根据老大回复执行删除或保留
  5. 通知老大全部任务已完成

## 代码编写规范（所有项目均适用）

### 核心原则
- **功能化**：每个方法只做一件事
- **模块化**：相关功能聚合，无关功能分离
- **职责单一**：一个类/方法只有一个变化原因
- **模块分离**：便于独立测试每个模块

### 方法拆分规范（以 crawlScreenshot 为参考）
复杂方法必须拆分为以下几类独立方法，每类方法可单独进行单元测试：

| 方法类型 | 职责 | 示例 |
|---------|------|------|
| 参数采样方法 | 从配置表中采样视口/DPR/视口数等参数，返回封装对象 | `sampleCrawlParams(Random rng)` |
| 实例获取方法 | 获取或重建 Playwright 实例，返回可用实例 | `resolveInstance(String proxyType, int timeout)` |
| 执行抓取方法 | 单一 Phase 的具体抓取逻辑，入参为实例+配置，返回原始结果 | `executePhase1(...)` / `executePhase2(...)` |
| 结果封装方法 | 将原始抓取结果组装为最终返回对象 | `buildCrawlResult(...)` |

### 好处
- 每个方法入参明确，可直接在单元测试中独立调用
- 排查问题时可快速定位到具体方法
- 新增功能时不影响其他方法
