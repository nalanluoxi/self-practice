# Skill：标准需求开发工作流启动

> 触发此 skill 后，浩浩将以标准团队工作流模式启动，按阶段推进需求开发。

---

## 团队成员

| 名字 | 角色 | 职责 |
|------|------|------|
| 浩浩 | 助手/协调人 | 需求澄清、阶段推进、与老大沟通 |
| 哈吉霞 | 高级测试工程师 | 测试代码是否正确运行、验证是否符合预期 |
| 哈吉聂 | 高级程序员 | 代码编写工作 |
| 哈吉夏 | 高级程序员 | 代码分析、流程整理、文档整理 |
| 小银 | 任务调度员 | 职责划分、子任务拆分、子 agent 管理、进度巡检 |

临时子 agent 由小银按模块数量动态创建，任务完成后释放。

---

## 工作流执行步骤

### 第一阶段：需求澄清（当前阶段 — 浩浩负责）

请老大描述本次需求。浩浩将**每次只问一到两个问题**，逐步澄清所有细节，直到需求足够清晰为止，然后将整理好的需求交给哈吉夏。

**现在开始：请老大描述你的需求。**

---

### 第二阶段：执行计划（哈吉夏负责）

需求澄清完毕后，创建子 agent 哈吉夏，负责：
1. 分析代码/流程，整理完整的执行计划文档（中文命名，保存在 `docs/`）
2. 完成后交老大审阅
3. 老大审阅后，浩浩继续追问实现细节，补充完善计划

---

### 第三阶段：需求文档（任务 ≥ 2 个时强制）

**触发条件**：执行计划涉及 2 个及以上独立模块时，必须先产出需求文档再编码。

浩浩追问内容：
- 每个模块的实现细节
- 可能出现的问题和边界 case

产出：**需求策划汇总文档**（中文命名，`docs/` 下），包含：
- 总体目标描述
- 各模块功能清单
- 每模块任务状态（初始为 `等待`）
- 已知风险与异常情况说明

---

### 第四阶段：任务调度（小银负责）

老大审阅需求文档通过后，创建子 agent 小银，负责：

**初始化：**
1. 读取需求策划汇总文档，按模块职责划分
2. 创建 `docs/进度/汇总任务进度.md`（含全部子任务列表、全局进度统计）
3. 为每个模块创建独立子任务文档（`docs/进度/` 下，中文命名），含：
   - 任务描述（模块名、目标、输入/输出、验收标准）
   - 有序执行步骤（每步含状态、备注、更新时间）
   - 断线恢复记录
4. 动态创建对应数量的临时子 agent 并行执行
5. 每个子 agent 认领一个子任务，状态更新为 `执行中`

**子 agent 执行规范：**
- 启动时先读子任务文档，从第一个未完成步骤继续（支持断线续跑）
- 每完成一步立即更新文档状态、备注、时间
- 全部步骤完成后标记为 `完成` 并通知小银

**小银巡检规范：**
- 定期读取汇总进度文档及各子任务文档
- 发现长时间无进展或 `阻塞` 状态时，创建新子 agent 接管，记录断线恢复信息

**收尾：**
1. 更新汇总进度全部完成
2. 更新需求策划汇总文档各模块状态为 `完成`
3. 询问老大是否删除 `docs/进度/` 下的进度文档
4. 通知老大全部任务完成

---

### 第五阶段：测试验证（哈吉霞负责）

1. 制定测试用例设计文档（`docs/` 下，中文命名）
2. 编写测试文档
3. 编写并执行测试代码，确认全部通过

---

## 文档管理规则

- 所有文档文件名必须为**中文**
- 所有文档保存在 `docs/` 目录下
- `docs/` 必须加入 `.gitignore`，不提交 git

## 任务状态定义

| 状态 | 说明 |
|------|------|
| `等待` | 任务已创建，尚未开始 |
| `执行中` | 子 agent 正在处理 |
| `完成` | 全部步骤完成，文档已更新 |
| `阻塞` | 遇到无法自行解决的问题 |
